## Cambio de producción

Solo cambia `core/src/wf_r17_referee.c`. Se conserva íntegro P0-01: silencio de emergencia,
retención del primer diagnóstico y protección frente a callbacks de audio posteriores.
No se han modificado recursos, música, sprites, dificultad, reglas ni cadencia.

1. En `primary2_7`, la comparación de `$1FA20` conserva los 32 bits del registro A1.
   En el código anterior se normalizaba el puntero antiguo a la base de un actor;
   esto no equivale a `CMPA.L` cuando hay bits altos distintos.
2. En esa misma ruta, `$1FA28` copia el nuevo objetivo. Un objetivo cero, incluido un
   valor con byte alto no nulo y dirección de bus cero, deja de provocar un bloqueo
   prematuro `$1C1688`. No se sustituye por otro luchador: se conserva el valor original.
   La función de aproximación existente ya contempla la lectura de vectores de ROM.
3. En `action7`, `$202BA`, se admiten las lecturas de objetivo cero que el original
   realiza contra ROM: X en `$06` es `$0654`; el byte de flags en `$32` es `$FF`.
   La operación sobre `$34` de ROM no se convierte en una escritura sobre un actor.
   Esto cubre tanto el objetivo enlazado como los globales `$1C1684` y `$1C1688`.
4. Se reproduce `CLR.B` sobre todo el byte de orientación y `MOVE.W` hacia la mitad
   baja de D0, conservando la mitad alta. Antes se limpiaba únicamente el bit 7 y no
   se reflejaba ese `MOVE.W` en los registros que conserva el port.

Las direcciones no representadas y diferentes de cero mantienen las guardas de
error. No hay un retorno de éxito indiscriminado ni un actor ficticio.

## Límites de la referencia ROM

La ROM se reconstruye del ZIP suministrado: `31e14-0.ic18` / `31e13-0.ic19`;
SHA-1 `a726c46f350723ea73158bc78055d17d418b14e2`.

El contraste ejecuta los bytes originales de las dos rutinas y, en los casos
públicos de conteo, el despachador desde `$1F914` hasta `$1F934`. Se utiliza un
intérprete limitado escrito para estas pruebas: rechaza instrucciones y accesos
no admitidos. Incluye autotests y registra las direcciones realmente ejecutadas.
**No equivale a validar con un emulador 68000 independiente.** `machine68k/Musashi`
no estaba disponible y no fue posible instalarlo en este entorno. El argumento
opcional `--machine68k` permite realizar después ese contraste; no se ha ejecutado
ni se certifica aquí esa ruta opcional. No se comparan CCR/SR, ciclos ni registros A
como contrato del port. Ningún intérprete se añade al ejecutable Saturn.

La foto del fallo identifica owner y dependencia, pero no contiene el valor de
los punteros ni un volcado completo. Las dos condiciones de bloqueo se reproducen
en las fuentes; **no se afirma haber reproducido exactamente tu partida física**
Hogan/Warrior contra Legion of Doom.

## Recuperación y ejecución

El paquete incluye fuentes acumulativas P0-01 + P0-02, un Git bundle recuperable,
un parche sobre P0-01 y otro acumulativo sobre el snapshot de R03. No incorpora
la ROM del arcade, recursos del disco, BIOS, toolchain ni compilaciones anteriores.

Desde la carpeta `source`, con la ROM original disponible:

```sh
python3 tests/test_referee_p0_02.py --rom-zip /ruta/wwfwfest.zip --sanitize --output build/p0-02
CC=clang python3 tests/test_referee_p0_02.py --rom-zip /ruta/wwfwfest.zip --sanitize --output build/p0-02-clang
python3 -m unittest discover -s tests/p0_02 -p test_rom_subset.py -v
python3 tests/run_p0_01_host.py --output build/p0-01
```

Para las pruebas de integración y mutación, colocar la imagen intercalada validada
como `source_assets/ROM68K.BIN`. Este es el mismo formato que usan los tests heredados.

```sh
python3 tools/build_runtime_tests.py --build-dir build/native-tests
python3 tests/test_referee_p0_02_integration.py --build-dir build/native-tests --baseline ../evidence/referee-p0-01.c --output build/p0-02-integration
python3 tests/test_referee_p0_02_mutants.py --output build/p0-02-mutants
python3 tests/run_initial_load_tests.py --assets /ruta/cd-completo --output build/full-suite
```

Los comandos con sanitizadores y enlace están verificados en Linux. No se ha
verificado su invocación directa en macOS. Los informes conservan las rutas de
esta ejecución; los scripts resuelven su raíz local al volver a ejecutarlos.

Para aplicar un parche a una copia de la base exacta, preservando los finales de
línea CRLF originales:

```sh

git -c core.whitespace=cr-at-eol apply /ruta/P0_02_sobre_P0_01.patch
```
